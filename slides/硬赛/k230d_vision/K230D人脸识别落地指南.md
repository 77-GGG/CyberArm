# CanMV K230D 人脸识别视觉模块落地指南

> 面向：清华大学硬件设计大赛 · ESP32-S3 双轮自平衡机器人项目
> 角色定位：K230D 作为**独立视觉模块**，完成人脸识别后通过 **UART 串口**把结果发给 ESP32-S3，主控制权仍归 ESP32-S3。
> 整理日期：2026-08（基于嘉楠官方文档与固件源码整理）

---

## 0. 一句话结论

K230D（128MB 内存）跑官方 **轻量版人脸识别**（`face_registration_lite` + `face_recognition_lite`，人脸检测 320 + 128 维特征识别模型），识别结果 **≤150ms 一次**通过 **UART1** 发给 ESP32-S3，模块供电 5V/2A，与 ESP32 共地交叉接线。官方示例代码直接可用，我们只需要：**① 按 K230D 内存调整分辨率 → ② 加一段 UART 输出 → ③ 注册人脸库**。

## 1. 硬件与环境

### 1.1 板卡参数（BPI-CanMV-K230D Zero，嘉楠 × 香蕉派）

| 项目 | 参数 |
|---|---|
| SoC | 勘智 K230D：双核玄铁 C908 RISC-V（大核 1.6GHz 支持 RVV1.0 + 小核 800MHz） |
| AI 算力 | 第三代 KPU，INT8/INT16；典型性能 ResNet50 ≥85fps、MobileNet_v2 ≥670fps、YOLOv5s ≥38fps |
| 内存 | **128MB LPDDR4** ← 这是所有限制的根源 |
| 存储 | TF 卡（固件与代码都放这里） |
| 摄像头 | 2 路 MIPI-CSI（2-lane + 4-lane），板子自带一条 MIPI 摄像头排线 |
| 显示 | MIPI DSI，最高 1080P（可选 LCD 屏，没有屏也能跑，见 2.4） |
| 网络 | 2.4GHz Wi-Fi（开发期可用来回传画面调试） |
| 扩展 | 40 针 GPIO：I2C / UART / SPI / PWM / ADC / JTAG |
| 电源 | USB Type-C 5V/2A |

### 1.2 接线（重要！）

K230D Zero 上电需要 **两根 USB 线**：一根供电，一根是虚拟串口（REPL，给 CanMV IDE 连）。

**K230D ←→ ESP32-S3 串口接线**（推荐用 UART1，走排针 8/10 号脚）：

```
K230D 排针 8  (GPIO3 / UART1_TXD) ──→ ESP32-S3 串口 RX
K230D 排针 10 (GPIO4 / UART1_RXD) ──→ ESP32-S3 串口 TX
K230D 排针 6  (GND)                ──→ ESP32-S3 GND      ← 必须共地
```

> **避坑**：排针 3/5 和 27/28 号的 UART 引脚与 CSI 摄像头 IIC 共用且有 4.7k 上拉，**别用它们**。
> 如果你用其他 UART（2/3/4），对照 40 针排针表选脚，并在代码里用 `FPIOA.set_function()` 重新映射（见 4.1）。

**供电**：K230D 用 5V/2A。车上是 2S 电池（7.4V）的话，需要一颗 5V/2A 以上的 DC-DC 单独给它供电（可参考你们电源树上已有的方案或 JW5357 类降压芯片）。**不要**从 ESP32 的 5V 引脚取电（ESP32 5V 通常带不动摄像头+NPU 的瞬间电流）。

### 1.3 刷固件（一次性）

1. 从 [kendryte/k230_canmv Releases](https://github.com/kendryte/k230_canmv/releases) 或 [嘉楠开发者社区](https://www.kendryte.com/resource) 下载 `CanMV-K230_micropython` 开头的 `.img.gz`（选最新正式版，例如 v1.0/v1.6 内核；文件名里能看到 nncase 版本）。
2. 解压得到 `sysimage-sdcard.img`。
3. Windows 用 Rufus、Linux 用 `sudo dd if=sysimage-sdcard.img of=/dev/sdX bs=1M oflag=sync`，烧到 **TF 卡**。
4. TF 卡插入 → 两根 USB 线接电脑 → 出现 `CanMV` 虚拟 U 盘 + 虚拟串口（REPL，通常 COM3 或 /dev/ttyACM0）。

### 1.4 开发环境

- **CanMV IDE**：从 [开发者中心下载](https://developer.canaan-creative.com/resource)，连接 REPL 串口即可运行 MicroPython 脚本。
- 固件里自带示例和模型：`/sdcard/examples/05-AI-Demo/`（AI Demo 源码）、`/sdcard/examples/kmodel/*.kmodel`（模型）、`/sdcard/examples/utils/`（anchors、人脸库目录）。
- 想随时看画面：K230D 支持 RTSP / MJPEG 网页视频流示例（`/sdcard/examples/network/`），开发期把画面拉到电脑上看，正式运行不需要屏幕。

## 2. 人脸识别原理与官方示例

### 2.1 识别流程（官方 AI Demo 框架）

```
摄像头 RGBP888 (640×360)
   │
   ├─ FaceDetApp：face_detection_320.kmodel（RetinaFace 类检测，320×320 输入）
   │      → 人脸框 + 5 个五官点（左眼/右眼/鼻/左嘴角/右嘴角）
   │
   ├─ FaceRegistrationApp：face_recognition_mobile.kmodel（112×112 输入）
   │      → 用 5 官点做 Umeyama 仿射对齐（Ai2d.affine 硬件加速）
   │      → 输出 128 维人脸特征向量
   │
   └─ database_search()：特征归一化后与数据库所有特征做余弦相似度
          score = dot(a,b)/2 + 0.5，score ≥ 0.75 判定为同一个人
```

人脸库就是 `/sdcard/examples/utils/db/` 下的一堆 `.bin` 文件，**文件名 = 人名**（建议用英文/拼音，避免编码问题），内容是 128 个 float32 特征。最多 100 人。

### 2.2 K230D 上必须用的版本（重要）

官方 AI Demo 表格里，K230 能跑、K230D 跑不了的 demo 很多。人脸相关选择：

| Demo | K230 | K230D | 说明 |
|---|---|---|---|
| face_detection 人脸检测 | √ | √ | 检测 |
| face_landmark 人脸关键点 | √ | √ | 5 官点 |
| face_liveness_rgb 活体检测 | √ | √ | 防止照片/屏幕攻击，可选加 |
| face_pose 人脸姿态 | √ | √ | |
| **face_recognition 人脸识别** | √ | ✗ | 完整版内存不够 |
| **face_recognition_lite 轻量人脸识别** | √ | √ | **K230D 用这个**（特征模型是更轻的 face_recognition_mobile.kmodel） |
| face_registration_lite 轻量人脸注册 | √ | √ | 配套注册脚本 |

### 2.3 官方两个脚本（已下载到 `reference/` 目录）

- `reference/face_registration_lite.py`：**离线注册**。把每人一张正面清晰照放到 `/sdcard/examples/utils/db_img/`（文件名 `zhangsan.jpg`），跑一遍，自动生成 `db/zhangsan.bin`。
- `reference/face_recognition_lite.py`：**实时识别**。主循环 → 检测 → 对齐 → 提特征 → 查库 → 画框显示结果。

### 2.4 K230D 的三处适配（官方注释明确要求）

1. `display_mode = "lcd"`：K230D Zero 默认输出 MIPI DSI，HDMI 相关模式不适用；**没有屏就设 `display_mode = "virt"`，并手动指定 `display_size = [640, 360]`**（virt = 虚拟显示，摄像头和 AI 照常跑，只是没人看画面——正式装车就是无屏模式）。
2. 分辨率调低：`rgb888p_size = [640, 360]`（代码注释原文：k230 保持不变，k230d 可调整为 [640,360]）。
3. 各 `display_size` 参数跟随实际输出。

## 3. 三步走实施计划

### M1：跑通官方 demo（半天）

1. 刷好固件，CanMV IDE 连上 REPL，先跑 `05-AI-Demo/face_detection.py` 确认摄像头、模型、屏幕/虚拟显示都正常（屏幕上能看到人脸框）。
2. 放一张照片 → 跑 `face_registration_lite.py` → 确认 `db/` 下生成 `.bin`。
3. 跑 `face_recognition_lite.py`（改好 2.4 的三处）→ 真人入镜能显示 `name: xxx, score: 0.9x`。
4. **调阈值**：`face_recognition_threshold = 0.75`（默认）。测你们的目标人物：认不出 → 降到 0.70~0.72；误识别人 → 升到 0.78+。每人多角度测 20 次，记下置信度分布。

### M2：加 UART 输出（半天，本目录已给代码）

- `face_recognition_lite_uart.py`：在官方识别循环里加 UART1 输出，协议见 `protocol.md`。做了三件事：
  1. **去抖**：连续 3 帧识别结果一致才对外发送（否则画面里人一闪而过、结果乱跳）；
  2. **限流**：结果帧最多 150ms 一帧（10fps 识别率下不会刷爆串口）；
  3. **心跳 + 帧校验**：校验和防误码，ESP32 能判断"视觉模块挂了"。
- **本协议的组帧与解析已用 PC 端仿真交叉验证过**（`tools/protocol_sim.py`，16 项全过：粘包/逐字节/噪声/坏校验 fuzz，见 `protocol.md` §5.1）。联调时帧解析不对，可先在本机重现再上板，省不少时间。
- 用 USB-TTL 接排针 8/10（交叉）先连电脑串口助手验证帧格式，再连 ESP32。

### M3：ESP32-S3 集成（1~2 天）

- `esp32_face_listener/esp32_face_listener.ino`：收帧、校验、解析出 `{id, score, 人脸中心(x,y), w, h}`，已经带一个"识别到目标人 → 让平衡车做动作"的骨架。
- 建议 ESP32 侧行为：识别到目标人物 → 车体朝向人脸移动/保持面向（用 x 中心偏离量做比例控制）；丢失目标 1s 内保持，超时回到待机。**人脸中心 → 转向控制**这个闭环是加分项，也是 K230D 给传感器价值最高的一处。

### 里程碑检查（对齐比赛初筛）

| 时间 | 交付 |
|---|---|
| M1 结束 | 人脸识别 demo 视频（带人脸框 + 名字） |
| M2 结束 | 串口协议文档 + 帧抓包记录（变相展示"通信与控制难点"） |
| M3 结束 | 整车演示：人走进画面 → 机器人转身面对他 / 机械臂做出欢迎动作 |

## 4. 关键代码片段

### 4.1 K230D 侧 UART 初始化（CanMV MicroPython）

```python
from machine import UART, FPIOA

fpioa = FPIOA()
# UART1 走排针 8/10：芯片 GPIO3 / GPIO4
fpioa.set_function(3, FPIOA.UART1_TXD)
fpioa.set_function(4, FPIOA.UART1_RXD)

uart = UART(UART.UART1, baudrate=115200,
            bits=UART.EIGHTBITS, parity=UART.PARITY_NONE, stop=UART.STOPBITS_ONE)
uart.write(b"...")   # 收：uart.read() / uart.readline()
```

> 如果 `fpioa.set_function(3, ...)` 报错或引脚对不上，用 `fpioa.help()` 看全部引脚当前功能，用 `fpioa.get_pin_num(FPIOA.UART1_TXD)` 查 UART1_TXD 当前映射。**先跑通官方 face_detection demo 再用串口**，出问题时能区分"视觉的问题"和"串口的问题"。

### 4.2 帧协议（详见 `protocol.md`）

```text
帧头 AА 55 | 类型 | 长度 | 载荷 | 校验和(前面所有字节求和取低8位)
```

载荷（结果帧）：`id(u8) | score(u8 = 0~100) | 人脸中心x(u16) | 人脸中心y(u16) | 宽w(u16) | 高h(u16)`，坐标基于 640×360 输入图。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| **128MB 内存紧张** | 只用 lite 版模型；识别+检测两个模型已占大头，不要再叠加 OCR/分割类 demo；不要同时开 RTSP 和识别 |
| 识别抖动/误识 | 阈值调优 + 去抖（本方案已做）；必要时叠加 `face_liveness_rgb`（活体检测，K230D 可跑）防止照片糊弄 |
| 光照变化大（户外/逆光） | 测试时记录；可加先验：检测置信度阈值 0.5 起步；车顶补光 |
| 摄像头排线松动/反插 | K230D Zero 是细排线，插反会烧，插前看丝印；固定用热熔胶/胶带 |
| 5V 供电不足导致重启 | 单独 5V/2A DC-DC；用示波器看启动瞬间压降；串口心跳能立刻暴露掉电 |
| 判断"AI 是不是在跑" | 心跳帧 + 每帧计时；`ScopedTiming("total", 1)` 开 debug 看耗时 |
| 中文人名的编码问题 | 库文件名与协议 id 都用英文/拼音，显示名字交给 ESP32 或上位机 |

**性能预期**：640×360 输入、320 检测 + 112 对齐，K230D 上人脸检测+识别整链路大约 10~20fps（官方 KPU 指标 YOLOv5s ≥38fps，人脸链路模型更小，实际以测为准）。对"人走进画面 → 机器人反应"这个时延完全够。
