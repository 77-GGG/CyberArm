# K230D ↔ ESP32-S3 串口通信协议 v1.0

> 适用：CanMV K230D（MicroPython）→ ESP32-S3（Arduino），UART1，115200-8-N-1。
> 设计原则：二进制帧、长度 + 校验和、无第三方库依赖、解析端抗粘包/断流。

---

## 1. 物理层

| 项 | 值 |
|---|---|
| 接口 | UART（K230D UART1，排针 8/10 = 芯片 GPIO3/4） |
| 波特率 | 115200，8 数据位，无校验，1 停止位 |
| 电平 | 3.3V TTL，直接对接 ESP32（ESP32-S3 也是 3.3V） |
| 接线 | K230D TXD → ESP32 RXD；K230D RXD → ESP32 TXD；**共地** |

## 2. 帧结构

所有帧统一格式，小端序：

```
+------+------+------+---------+------+
| 帧头 | 类型 | 长度 | 载荷    | 校验 |
| 2B   | 1B   | 1B   | LEN 字节 | 1B  |
+------+------+------+---------+------+
```

| 字段 | 偏移 | 长度 | 说明 |
|---|---|---|---|
| 帧头 | 0 | 2 | 固定 `0xAA 0x55`（同步用） |
| 类型 TYPE | 2 | 1 | 见下 |
| 长度 LEN | 3 | 1 | 载荷字节数（0~255） |
| 载荷 PAYLOAD | 4 | LEN | 按类型定义 |
| 校验 SUM | 4+LEN | 1 | **帧头起所有字节之和 & 0xFF** |

### 2.1 类型定义

| TYPE | 方向 | 名称 | 载荷长度 | 说明 |
|---|---|---|---|---|
| 0x01 | K230D→ESP32 | 识别结果 RESULT | 10 | 每 ≤150ms 最多一帧；身份变化/连续 3 帧确认时立即发 |
| 0x02 | K230D→ESP32 | 心跳 HEARTBEAT | 2 | 每 1s 一帧，`alive` + 温度(可选，暂填 0) |
| 0x03 | K230D→ESP32 | 状态 STATUS | 1+N | `code`：0=模型加载完成 1=识别启动 2=数据库加载 N 人 0xFF=错误；后面可跟字符串 |
| 0x04 | ESP32→K230D | 查询 QUERY | 0 | K230D 收到后回一帧 0x03 状态（用于 ESP32 复位后同步） |

## 3. 各帧载荷

### 3.1 RESULT (TYPE=0x01, LEN=10)

```
偏移 0: id       u8   数据库索引（0~99）；未知/无人 = 0xFF
偏移 1: score    u8   相似度 0~100（= 余弦分 ×100，阈值 75 对应 0.75）
偏移 2: cx       u16  人脸中心 X（0~639，640×360 坐标系）
偏移 4: cy       u16  人脸中心 Y（0~359）
偏移 6: w        u16  人脸框宽
偏移 8: h        u16  人脸框高
```

无脸/不认识时：`id=0xFF, score=0, cx=cy=w=h=0`，LEN 仍为 10。

### 3.2 HEARTBEAT (TYPE=0x02, LEN=2)

```
偏移 0: alive   u8  固定 0x01（预留：0x00=异常）
偏移 1: temp    u8  板卡温度近似值（MicroPython 暂不可读时填 0）
```

### 3.3 示例：完整 RESULT 帧（十六进制）

识别到数据库 id=3，得分 92%，人脸中心 (320,180)，框 120×120：

```
AA 55 01 0A 03 5C 40 01 B4 00 78 00 78 00 4E
├─帧头─┤ ├类型┤├长┤ ├id┤├分数┤ ├─cx=320─┤ ├─cy=180─┤ ├w─┤ ├h─┤  ├校验─┤
```

- 长度 LEN = 10（`0x0A`）：id(1) + score(1) + cx(2) + cy(2) + w(2) + h(2)
- 帧头起所有字节求和：`0xAA+0x55+0x01+0x0A+0x03+0x5C+0x40+0x01+0xB4+0x00+0x78+0x00+0x78+0x00 = 0x34E`，低 8 位 **`0x4E`**
- 无脸时 id=0xFF、score=0、其余 0，LEN=10。

## 4. 接收端状态机（ESP32）

```
IDLE ──0xAA──▶ SYNC1 ──0x55──▶ TYPE ──▶ LEN ──▶ PAYLOAD(读 LEN 字节) ──▶ CHECKSUM ──▶ 解析/回到 IDLE
 ▲                │
 └──── 非 0x55（且非 0xAA）回到 IDLE 同步头重找 ────┘
```

实现要点（见 `esp32_face_listener.ino`）：
1. 主循环 `while (Serial1.available())` 里逐字节喂状态机，天然抗粘包；
2. 校验失败直接回到 IDLE，不重置整条流（不要清空缓冲区，避免丢帧头）；
3. 用 `millis()` 监控心跳：>3s 没收到 → 判定 K230D 掉线，走降级/保护逻辑；
4. 帧内多字节字段全部小端，ESP32 用 `payload[2] | (payload[3] << 8)` 解包（代码里即这样实现）。

## 5. 通信语义约定

- K230D 只主动上报，不轮询；ESP32 复位后发 0x04 查询，拿 0x03 状态帧（含数据库人数）确认模块在线；
- 身份去抖：连续 3 帧（约 300ms）结果一致才发 RESULT；身份变化立即发一帧；
- score 建议 ESP32 侧再做一层滤波（一阶低通或取最近 5 帧平均），画 UI/做动作更平滑；
- 波特率 115200 下 10B 帧≈0.9ms，10fps 上报只占带宽 0.09%，完全够用；如需提升到 460800 两边同步改即可。

### 5.1 校验能力（实测）

用 `tools/protocol_sim.py`（组帧方与解析方逐字转写自两侧代码）做了 500 帧 fuzz 实测：

| 指标 | 结果 |
|---|---|
| 干净帧解析率 | 442/442 = **100%**，0 丢失 |
| 帧内单字节噪声拦截率 | 57/58 ≈ **98.3%**（8 位求和校验的理论值 1−1/256） |
| 幽灵帧（凭空解析出合法帧） | **0** |
| 同步恢复 | 帧间/帧内噪声后下帧立即恢复 |

**已知限制**：8 位求和校验会以 ≈1/256 概率被单字节噪声"凑对"（实测 1/58）。对本项目（短帧、115200、室内短距离）足够；若后续要求更严，可升级 CRC8 并保留现有帧头/长度字段（接收端状态机不用改，只改校验函数）。

## 6. 调试帮助

- 电脑上验证：USB-TTL 接 K230D 排针 8/10（交叉），串口助手开十六进制显示，应看到 `AA 55 02 02 01 00 xx` 心跳流；
- K230D 侧看发送：用 CanMV IDE 的串行终端（REPL 串口是另一根 USB，不冲突），代码里 `print()` 调试信息走 REPL；
- 常见问题：全是 `AA 55` 且无后续 → 类型/长度解析错，检查你的解析器是否把 0xAA 0x55 误当类型；只有校验错误 → 检查小端序和 u16 拆包方式。
