# CyberArm 固件实现方案

版本：1.0｜2026-09-14｜状态：开发方案与协议草案，尚未编写/烧录运动固件。

## 1. 固件的作用与工具

固件是机械臂的执行管家：电脑给出验证后的动作，它检查能否执行、安排五关节与夹爪的速度、输出 PWM、处理停止并回报执行进度。3D 显示与首期复杂 IK 放在电脑，固件先做到少量动作可靠可测。

沿用现有 PlatformIO + ESP32-S3 Arduino 环境及 PCA9685 库。新增代码前记录并固定已构建通过的平台、Arduino core 与依赖版本，不仅凭在线最新文档升级全部依赖。ESP32-S3 支持 USB CDC，但接口需接到原生 USB，不能混淆板上的 USB 转串口口。[Espressif USB 文档](https://docs.espressif.com/projects/arduino-esp32/en/latest/tutorials/cdc_dfu_flash.html)

## 2. 模块

| 模块 | 内容 | 桌面测试方法 |
|---|---|---|
| MotionCore | 同步轨迹、状态机、限位、制动、进度 | 独立 C++，不引用 Arduino/Wire |
| RobotConfig | 关节顺序、FK、校准、速度限制、版本 | 同一参数与对照样本 |
| HostProtocol | 有界 JSON 收包、去重、响应 | 模拟字节流 |
| Supervisor | 控制租约、模式、使能、故障、队列 | 虚拟单调时钟 |
| ServoOutput | 关节角转脉宽、六路提交、I2C/OE | FakeHAL 后接开发板 |
| Telemetry | 指令角、状态、队列与故障 | 不伪造实测角 |
| VisionLink | 后续 UART、观测转发、时钟同步 | 注入视觉数据 |

建议目录为 lib/MotionCore、src/app、src/hal、src/protocol、src/vision、test。先写最小可运行链路，不预先创建大量空任务。

独立构建 SIM 和 HARDWARE：SIM 使用虚拟时钟/输出，绝不初始化真实 PWM；HARDWARE 上电 OE 禁止，配置/校准无效不能普通运动。不能用一条普通网络命令悄悄切换到实物。桌面模拟核心完成后可接 ESP 看波形，不需要提前打印。

## 3. 周期、并发与资源

控制任务初始按绝对 20 ms 周期调度，避免连续 delay(20) 叠加执行耗时。I2C 输出只由控制任务管理，USB/UART 接收提交有界消息，日志/显示低优先级。FreeRTOS 提供任务工具，但多核不自动解决竞态，要明确队列和状态所有者。[Espressif FreeRTOS 文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/system/freertos_idf.html)

收包不阻塞插补，NVS 写入/日志不在控制任务执行。急停输入锁存并走硬件禁止路径；中断不解析 JSON 或写 I2C。严重周期超时进入停止/故障，不追赶一串过期 PWM 帧。

初始普通队列最多 16 条、每行最多 2048 字节，具体资源在实现时固定并通过握手报告。满队列报 QUEUE_FULL，不覆盖未知指令；STOP 走独立通道。所有数值、数组、字符串、帧长均检查，解析超时丢弃残帧并恢复同步。

## 4. 标定和输出

映射顺序：关节角 → 装配零位/方向 → 每路实测映射 → 微秒。不能假设两种舵机均能转满 180°，或 1000–2000 μs 精确对应 0–180°。

现有 writeAngle() 只按最小/最大脉宽线性映射，centerPulseUs 只供 center()。正式关节映射另写，再调用微秒接口。高级命令越界整条拒绝，不能靠底层静默截断并返回成功。现有库写入返回值也不能证明实物到位，需要补充 I2C 错误检查。

六路共享逻辑采样时间，在一个控制周期提交。PCA9685 公共频率和寄存器提交能力可减少偏差，但跨通道时序须测量，不能保证不同负载舵机物理同步。[NXP 数据手册](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf)

50 Hz 的 20 ms 周期分为 4096 计数，单步约 4.88 μs。这是时间量化推算，不是角度精度。模拟器后续加入可选量化、滞后、回差扰动，用明确假设显示结果，不能当作实测舵机模型。

## 5. 运动与停止

SEQ 首版实现起止速度为零的 MoveJ，各轴采用相同归一化函数和总时长。可选五次插值 s(u)=10u³−15u⁴+6u⁵，q=q0+s(u)(q1−q0)。总时长依据全段速度/加速度极值选定，不仅检查平均速度。每个关键点停下再下一条，预览如实展示停顿。

INT 后续用于手柄/视觉，只保留最新有效目标，从当前指令位置和速度连续重规划；不能每收目标都重启起止速度为零的曲线。边界减速、目标突变与丢帧测试通过后才开放。

TRJ 后续定义分段轨迹时间基准、容量、前视长度和缺段停止；首期 capability=false，不能用高频 MoveJ 冒充流式轨迹。

STOP 从当前指令位置/速度生成制动轨迹，检查全段限位与碰撞。暂停/继续在停止后重新规划，不能沿旧时间轴跳转；急停不等待普通减速队列。夹爪可独立或同步动作，但开度不代表夹紧力。

## 6. 状态与参考姿态

BOOT → DISABLED → READY → EXECUTING → READY；运行可进入 STOPPING、FAULT、ESTOP。停止至零指令速度后按原因进入 READY/DISABLED。FAULT/ESTOP 恢复重新自检，不自动回到执行。

READY 要求版本匹配、参数有效、输出设备存在、参考姿态建立和使能条件通过；运动还需有效控制租约。SIM 可设初始姿态；HARDWARE 断电后姿态未知，NVS 上次指令角不能当真实位置。

标定模式按工装支承、独立舵机/拆开传动等流程逐轴建立基准，不允许未知装配姿态下六路同时自动回中。增加绝对位置传感器并验证后，才改变启动策略。

## 7. USB 协议草案

UTF-8 按行 JSON，普通文本日志不得混入业务串口。hello 返回 protocol_version、boot_id、模型/限制/标定/场景版本、支持模式、帧长/队列上限及传感能力；当前 joint_feedback=false。

| 命令 | 作用 | 首期 |
|---|---|---|
| hello / get_state | 握手和状态 | 是 |
| claim_control / heartbeat / release_control | MCU 租约 | 是 |
| enable / disable | 明确使能或禁止输出 | 是 |
| move_j / grip | 关节/夹爪动作 | 是 |
| stop / clear_fault | 停止、自检请求 | 是 |
| jog / stream_segment | 连续点动/流式轨迹 | 验证后开放 |
| set_vision_mode | 视觉配置 | 后续 |
| write_calibration | 标定持久化 | 后续，仅停止且队列清空时 |

以下只表示消息格式，标识和角度不是实机可用参数：

```json
{"v":1,"session":"example","id":42,"lease":"example","cmd":"move_j","model_id":"example","limits_id":"example","calibration_id":"example","scene_id":"example","q_rad":[0,0.1,-0.1,0,0],"gripper_ratio":0.3,"duration_ms":1500,"expires_at_device_ms":123456}
```

gripper_ratio 是标定开度区间的比例，不是力或实测毫米。过期时间用设备单调时钟，经同步并计入误差，不能直接用 PC 时间。schema 固定五关节，拒绝非有限值、未知枚举或缺失版本。

同会话同 ID 同内容返回已有状态，不重新执行；同 ID 不同内容拒绝。去重采用有界缓存与单调序号窗口，滑出窗口的旧 ID 不作新命令。重启 boot_id 改变，PC 取消待确认动作并重新握手。ACK 超时先查询状态，不能盲目重发运动。

生命周期：ACCEPTED、STARTED、COMPLETED_COMMAND、CANCELLED、REJECTED。STARTED 在真正开始插补时发出。COMPLETED_COMMAND 仅指插补指令结束，不证明物理到位。状态含命令 ID、q_target、q_commanded、q_measured:null、夹爪指令、队列和故障。

排队等待与消息有效期分开：在有效期内接收，开始时仍复核租约、场景、预期前驱状态与最大等待时间；过时视觉动作取消。来源切换或停止使旧队列失效。场景/模型版本变化需重新验证轨迹。

错误码至少有 INVALID_ARGUMENT、OUT_OF_LIMIT、PATH_BLOCKED、NO_SOLUTION_FOUND、VERSION_MISMATCH、NOT_ENABLED、NO_CONTROL、STALE_COMMAND、QUEUE_FULL、UNSUPPORTED、IO_ERROR。

## 8. MCU 能力边界

SDK 检查后，MCU 仍检查关节/时间/速度/加速度/租约/版本，以及本地支持的 FK 工作边界和简化碰撞。实际插补必须与预览一致。复杂场景由 PC 规划，但执行绑定固定场景快照/版本，更新场景先停止再验证。

制动包络在运动允许前检查，不能到边界才停。当前无动态未知障碍的可靠实时检测。角度、电流、温度、堵转、抓取成功等需要传感器和验证，不由已有 PWM 接口推断。

OE 拉高禁止 PWM，不是断电制动。复位/I2C 故障可能导致姿态失去保持，输出禁止、供电切断与支承需联合验证。

## 9. 开发台阶

1. 桌面模拟核心：hello/get_state、MoveJ、STOP、错误，使用虚拟时钟验证轨迹和边界。
2. ESP 无输出：验证 USB 和状态机，OE 禁止，记录周期。
3. 单路波形与独立舵机：先假负载/仪器观察 PWM，再标定，不需要已打印整机。
4. 六路执行逻辑：同步、I2C 错误、失联、停止、重启，对照模拟器日志。
5. 已装配小范围联调：建立实物参数/误差余量，逐步扩大范围。
6. INT、视觉、脱机等扩展逐项验证，每项单独声明能力。

本轮只完成方案，无需用户自行写固件。后续可逐步交付代码与测试；真实板型、引脚、标定及停止电路在对应硬件阶段确认。
