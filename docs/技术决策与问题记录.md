## 本轮变更与后续记录方式

2026-09-14：覆盖总设计与视觉设计；增加条件可达、整条路径/制动边界、统一控制入口及先仿真后打印流程；补充固件模块、命令语义、无反馈显示、启动未知姿态、视觉时钟和租约；新增固件方案与本文件。未改动模型几何、STL、控制代码，未烧录设备。

2026-09-14（性能）：按用户反馈定位并修复规划内核的两处慢点——路径检查的保守 pad（夹爪方向被放大 15 倍，导致窄相碰撞查询按大 ceiling 计费）与 IK 的解析雅可比取错关节轴；新增热启动通道和夹爪逐网格实测扫掠半径，检查改为先分段。判据未放松，接受段密集复测零漏检，记录见 [上位机预览性能优化_20260914.md](上位机预览性能优化_20260914.md)。未改动模型几何、限位、速度上限、前端与 C++ 核心。

2026-09-14（性能落地到两端）：确认算法只有 planner.py 一份，网页端开发态经 HTTP 直接调用因而自动生效，前端 dist 因源码未变无需重建（三处 index.html 与 JS 的 SHA-256 一致）。Electron 端重新冻结后端并把新 cyberarm-backend.exe（当时 SHA-256 A5B8323E…B2A0，后于 2026-09-15 再次冻结为 2856759D…FB77）同步到 desktop/build/frozen、desktop/stage/backend 与 desktop/dist/win-unpacked/resources/runtime/backend。新增启动期预热：每个规划进程的首次任务要付约 1 秒的 import 与碰撞数据解压，现改为 lifespan 内向池里投两个 warm_worker 任务。可达采样向量化后 95.6 ms 降到 33.4 ms，点数与坐标不变。细节见 [上位机预览性能优化_20260914.md](上位机预览性能优化_20260914.md) 第 13 节。

2026-09-15（首次预览的余量）：把那份一次性成本拆开，发现 planner 在模块级 import scipy.optimize，单这一项就要 653 至 677 ms（整份 import planner 为 641 ms，两者量级相同即该项是主因），而它只在冷种子分支（远离工作空间的目标）才用得到。改为 planner.least_squares_solver() 函数内惰性导入后，导入 planner 降到 127 ms：网页端窗口刚显示就点预览从 784 ms 降到 248 至 446 ms，稳态 61 至 128 ms。warm_worker() 另把求解器加载放到后台线程，让它在窗口打开期间完成；打包脚本显式声明 --hidden-import scipy.optimize，避免函数内导入被字节码扫描漏掉。plan_job 的预览 15 点也改为批量正运动学（与旧循环最大差 5.551e-14 mm）。冻结产物重建并同步三处，新 cyberarm-backend.exe SHA-256 2856759D…FB77，桌面版首次预览 792 至 986 ms、随后 49 至 82 ms。未改动碰撞判据、限位、速度上限、模型几何、前端与 C++ 核心；细节见 [上位机预览性能优化_20260914.md](上位机预览性能优化_20260914.md) 第 13 节。
