# CyberArm 机械臂系统设计文档

版本：2.1｜更新：2026-09-16｜状态：仿真与实机同步软件已实现，实体硬件待逐轴标定和验证。

本版根据用户确认覆盖旧版。主方案为现有 RevC 五关节机械结构、3 个 MG996R 和 3 个 MG90S，先完成上位机与模拟控制器的软件验证，再打印和装配。允许为运动学、干涉、支承、布线及视觉安装修改模型；维持现有五轴拓扑，不追求任意六维末端姿态。

本文同时记录目标设计与当前实现。现已有 RevC 总装、打印资产、运动预览、USB CDC 实机桥接、六路校准界面及 ESP32-S3/PCA9685 轨迹固件；实物接线、负载和精度仍需逐项验证。实现状态与未决问题以 [技术决策与问题记录](技术决策与问题记录.md) 为准。本文与同名 PDF 的历史版本可能存在更新时差。

## 1. 产品目标与开发顺序

制作一个可独立用于仿真的中文机械臂上位机：显示真实模型、关节操作、末端目标、条件可达范围、碰撞提示、关键帧、动作回放和状态。其后通过 USB 连接 ESP32-S3 驱动实物，再接入 K230D 视觉感知和更多操作设备。

借鉴 Dummy 的模型联动、示教、顺序命令与实时目标控制思想，使用适合本机的运动学和 PWM 执行器。DummyStudio 发布包不是本项目源码底座，RoboDK 保留为可选适配器，不作为第一版运行依赖。[Dummy 官方说明](https://github.com/peng-zhihui/Dummy-Robot)

开发顺序固定为：模型与参数核对 → 纯软件操作及边界验证 → 模拟控制器/固件逻辑验证 → 打印准备审查 → 接口试装与整机打印 → 实物标定和低速联调 → 视觉扩展。软件验证可以证明算法与协议行为，实物回差、装配误差、温升和承载仍须制作后测量。

## 2. 机械与硬件基线

| 轴 | 功能 | 舵机 | 模型节点 | 建议通道 |
|---|---|---|---|---|
| J1 | 底座回转 | MG996R | J01_Base_yaw | 0 |
| J2 | 肩俯仰 | MG996R | J02_Shoulder_pitch | 1 |
| J3 | 肘俯仰 | MG996R | J03_Elbow_pitch | 2 |
| J4 | 腕旋转 | MG90S | J04_Wrist_roll | 3 |
| J5 | 腕俯仰 | MG90S | J05_Wrist_pitch | 4 |
| G | 夹爪开合 | MG90S | 四连杆与齿轮联动 | 5 |

通道是设计约定，接线完成后确认，不是已核验线束。G 不计入控制末端刚体姿态的自由度。所有舵机沿用已有记录的 5 V 供电基线；实际脉宽、方向、可动角域和零位均未标定。

机械源文件为 mechanical/arduino_reference_revC/Arduino_Replica_RevC_Connections.blend。打印 STL 仅是制造输出，不能代替机器人参数与关节层级。现有 ±30° 关节和 ±8° 夹爪范围仅为历史预览范围，不是软件最终边界或实物安全角域。

| 硬件 | 职责 | 目前约定 |
|---|---|---|
| ESP32-S3 | 通信、控制权、轨迹执行、约束和状态 | 延续 PlatformIO + Arduino；实际板型/USB 口待核对 |
| PCA9685 | 六路舵机 PWM | 初始 50 Hz；GPIO8/9 是库默认 I2C 引脚，非最终 PCB 分配 |
| K230D BOX + GC2093 | 后续图像采集和检测 | 使用板卡专用 CanMV；详见视觉文档 |
| MPU6050、OLED | 可选姿态输入、状态显示 | 预留接口，首版仿真不依赖 |
| OE、实体停止装置 | 输出禁止与实物停止 | GPIO、上拉及供电切断电路待设计 |

舵机、控制逻辑、视觉板分电源域并共地，大电流不通过开发板稳压器。原复核中的 5 V/15 A 是选型预算，不是本批实测电流或负载认证。肩部承载、底座支承及腕部负荷问题保留，不能通过扩大软件范围解决，详见 [RevC 结构复核](../mechanical/arduino_reference_revC/audit_20260907/结构载荷与电流复核_20260907.md)。

## 3. 模型、坐标与版本管理

从 Blender 导出显示 GLB、简化碰撞体和机器人参数。保留原始 RevC 作对照；需要改变几何时建立新的机械版本及变更记录，重新生成对应打印件，避免新模型配旧 STL。

机器人参数至少包含：模型版本、几何哈希、关节顺序、父节点、本地旋转轴、固定变换、模型零姿态、软限位及其依据、速度/加速度限制、舵机映射、夹爪约束、工具中心点 TCP、碰撞体、基座与桌面关系。仿真角域与已标定实物角域分别保存；未知实物参数为空，不能用 0 或全行程代替。

内部使用右手坐标系、米和弧度；界面显示毫米和角度，协议字段以 _rad、_m、_ms 显式标注单位。基座 Z 向上，X 作为任务前方，Y 按右手系；Blender 场景通过显式变换映射到基座，不假设原模型已经匹配。

模型零姿态、实物装配零位和舵机电气中位分别定义。TCP 第一版固定在工具/夹爪安装参考系中，抓取点与夹爪开度另行表示；不要让 TCP 无意随开度变化。模型中的负载代理点也不能直接当作已标定 TCP。

夹爪是闭链机构，GLB 不承担 Blender 原生表达式执行。运行时重建齿轮和四连杆求解，跟随当前装配分支，检查奇异点、干涉与开度单调区间。固定动画可以演示，不能替代任意开度求解。

相机第一版按外置固定支架规划，避免增加腕部负担。预留 camera_frame、相机外参、视锥、线缆通路及可替换支架接口；腕上相机作为后续可选结构，要重新核验质量、全程干涉及手眼标定。

影响轴心、连杆尺寸、TCP、碰撞体或限位的变更，都使旧工作空间缓存和动作轨迹失效，必须重新验证。仅材质变化可不改变运动学版本，但仍记录显示资产版本。

## 4. 可达范围与边界控制

边界不是预先填写的半径/高度矩形。本机允许的运动由关节角域、目标姿态约束、碰撞、任务区域及制动余量共同决定。旧版固定工作空间指标不再沿用，待模型计算输出。

| 层次 | 含义 | 界面/执行行为 |
|---|---|---|
| 几何可达 | 给定模型和关节范围存在位置解 | 显示采样得到的空间分布 |
| 条件可达 | 加上朝向、开度、桌面和禁入区后仍有解 | 随当前工具和模式更新 |
| 路径可执行 | 当前状态至目标的轨迹及停止轨迹通过检查 | 才能排队执行 |
| 实物工作区 | 加上标定、误差余量和负载限制 | 制作后逐步验证和收缩 |

工作空间点云/体素是可视提示，必须标明采样分辨率与条件；采样到可行点不证明整个网格单元可行，未采到点也不证明绝对不可达。执行时重新求解和检查具体轨迹。

交互分为“位置优先”和“带朝向约束”。位置优先在满足目标 XYZ 后选择更连续的可行姿态；带约束模式说明哪项朝向是硬约束、哪项是偏好，显示实际可实现朝向和残差。不能声称任意两项姿态与 XYZ 在所有位置均独立可控。数值 IK 未收敛显示“当前未找到解”，与已证明越界分开。

拖动目标显示为独立标记。无效目标变色并展示原因，机械臂预览停留在最后有效轨迹状态；最近可行点可作为候选显示，不自动替代原目标下发。脚本/API 接收明确错误；视觉目标越界则丢弃或暂停跟踪，不直接截断到边缘。

每次运动都经过同一流程：

1. 检查模式、控制权、版本、当前指令状态、有限数值及单位。
2. FK/IK 求解，检查各关节、夹爪与目标残差；偏好上一组配置，避免跳解。
3. 生成带时间的关节轨迹；MoveJ 检查关节插补路径，MoveL 沿直线连续求解并检查朝向约束。
4. 检查全链路自碰撞、桌面、环境禁入区、夹爪和登记的负载包络；检查速度/加速度和奇异区。
5. 纳入制动轨迹与误差余量，通过后才能执行。接近边界的点动降速；剩余范围不能容纳停止动作时拒绝继续靠近。
6. 运行时 MCU 复核执行状态；场景、控制权或目标失效时取消待执行轨迹并受控停止。

碰撞检查采用简化碰撞体与保守裕量；运动段采用连续扫掠，或按最大位移/角位移界自适应细分并包含未采样位移裕量。不能只检查端点，也不能将固定抽样无碰撞写成严格连续无碰撞。先验证基本直达路径，自动绕障留作扩展；找不到安全路径时不擅自执行。

软件能约束模型中的指令轨迹。真实无反馈舵机的误差和外界未知障碍仍可能使实物偏离模型，实物阶段须量化误差并设置余量。

## 5. 操作方式与统一入口

| 操作入口 | 行为 | 阶段 |
|---|---|---|
| 关节滑块、数值输入 | 五关节与夹爪独立调试，保存姿态 | 首版 |
| 末端拖拽、坐标输入 | 位置优先/带朝向约束，展示可达性 | 首版 |
| 键盘点动 | 基座/工具坐标系增量运动，松键停止 | 首版验证后开放 |
| 关键帧、时间轴 | 示教点、MoveJ、等待、夹爪、有限循环 | 首版 |
| Python SDK、脚本 | 组合动作、订阅状态、批量离线验证 | 首版 |
| 手柄、摇杆、示教器 | 速度点动、死区、按住使能 | 接口预留 |
| 空间控制器 | 输出位姿/速度意图，明确坐标系 | 接口预留 |
| 人脸/指尖跟踪 | 目标误差生成有期限的运动意图 | 后续 |
| 视觉选物抓取 | 平面定位、接近、夹取、抬起序列 | 后续 |
| 手势、语音 | 映射允许的离散动作，去重、防误触发 | 后续，语音识别部署另定 |
| MPU6050 镜像 | 标定后映射部分关节/方向 | 后续，不是完整人体动捕 |
| RoboDK、外部规划器 | 通过同一 SDK/适配器提交任务 | 后续验证 |

所有入口转换成 MotionIntent：来源、意图类型、参考坐标系、目标/约束、有效期、版本与来源序号。意图经过规划校验才形成执行指令，插件不能直接写 PWM。move_j、move_l、jog、grip、stop、get_state、run_action 为 SDK 语义，是否支持由能力握手决定。

借鉴 Dummy 的顺序与实时命令区分，不兼容其原协议：SEQ 按队列执行，INT 只保留最新有效目标并连续重规划，TRJ 为后续有时间戳的轨迹缓冲。三者独立，不能把实时目标堆成历史队列。首个可运行版本只开放 SEQ；点动先用离散小步验证，连续 INT 在连续性/停止测试后开放，TRJ 暂报不支持。

任一时刻仅有一个运动来源持有 MCU 批准的控制租约。PC 服务仲裁界面、脚本与手柄；MCU 最终仲裁 PC、独立视觉与示教器。来源切换先停止、清空旧目标、更新租约，再接收新来源。停止不依赖当前运动持有者；失焦、松使能、手柄脱落、心跳超时终止点动，重连不恢复旧动作。

## 6. 软件架构与仿真一致性

```text
Three.js / 键盘 / 手柄 / Python 脚本 / RoboDK 适配
                     ↓ MotionIntent
Python 本机服务：来源仲裁、五轴 IK、路径与碰撞检查、记录
                     ↓ 同一命令协议
        SimTransport 或 USB SerialTransport
                     ↓
模拟控制器 或 ESP32-S3：状态机、插补、执行约束
                     ↓
虚拟输出 或 PCA9685 → 六路舵机
```

前端负责交互和显示，不独立决定路径安全。后端计算的实际关节轨迹驱动模型；显示目标、已接收轨迹与当前指令姿态，不将目标立即画成机器人已经到达。

模拟/硬件模式共用 API、错误、控制权与记录格式。固件的状态机、关节轨迹与基础约束做成不依赖 Arduino 的 C++ 核心，在桌面模拟控制器和 MCU 复用，硬件读写通过小接口替换。Python IK/高级碰撞规划与 MCU FK/基础检查使用同一参数和交叉验证样本，确保单位、轴方向和插补定义一致。

首期 PC 负责完整规划，MCU 负责基础 FK、关节/任务边界与简化碰撞复核；未完成这些复核前只能运行模拟或隔离的单舵机标定。后续脱机须移植并验证所需 IK/场景约束，再开放对应能力，不能在拔掉 PC 后默认拥有同等功能。

场景、机器人、工具、限制与标定使用组合版本标识。执行前核对预览起点、轨迹版本与 MCU 当前指令状态；状态变化后旧预览不可直接发送。复杂环境变化先停止并重新规划，未登记环境不能由软件保证无碰撞。

## 7. 固件方案摘要

固件是 ESP32-S3 上的运动执行程序，将验证后的关节动作变成稳定 PWM。3D 显示和首期复杂 IK 放在电脑。延续 PlatformIO + Arduino，先不上完整 ROS 或重做控制硬件。详细方案见 [固件实现方案](固件实现方案.md)。

| 模块 | 任务 |
|---|---|
| Board/HAL | USB、I2C、UART、OE、停止输入；SimHAL 替代真实输出 |
| RobotConfig | 六路通道、校准、限位、FK 参数和版本 |
| Protocol | 有界收包、JSON 校验、命令 ID、响应和超时 |
| Supervisor | 状态机、租约、使能、停止和故障锁存 |
| MotionCore | 同步插补、速度/加速度、限位及停止轨迹 |
| ServoOutput | 关节角到校准脉宽，输出与 I2C 错误检查 |
| Telemetry | 指令状态、队列、故障和可用传感器 |
| VisionLink | 后续接收 K230D 观测并验证时效 |

控制周期初始 20 ms/50 Hz，状态上报约 10–20 Hz，显示争取 60 fps，均为设计起点而非实测。控制任务不等待 USB、视觉、日志或屏幕，不在中断里解析 JSON 或写 I2C。执行状态由一个任务拥有，其他任务通过有界队列提交请求。

q_target 为目标，q_commanded 为插补指令，q_measured 当前为空。生命周期区分 ACCEPTED、STARTED、COMPLETED_COMMAND、CANCELLED、REJECTED。输出最后一个点不等于舵机实测到位或物体抓牢。

## 8. 视觉扩展

K230D BOX 使用 GC2093 处理图像和检测，输出坐标系、置信度、采集时间、帧序号及标定版本，不输出 PWM。保留 UART1/GPIO40、41 与 ESP 通信的方向，针序、电平与 ESP 引脚在实物前确认。[官方板卡说明](https://wiki.alientek.com/docs/Boards/Kendryte/DNK230D/start-guide/k230d-box-introduction/)、[UART 例程](https://wiki.alientek.com/docs/Boards/Kendryte/DNK230D/example-base/uart/)

首期视觉策略在 PC：K230D → ESP 转发观测 → PC 意图/规划 → ESP 执行。模拟阶段注入同格式观测；独立视觉模式待 MCU 完成所需算法与约束后启用，两种模式互斥。

原始视频不经低速 UART，另设图像链路。首期固定相机、桌面平面定位，预留内参、畸变、外参和工具变换。二维检测不能直接当三维坐标，手眼相机/深度任务单独验证。

板卡 uptime 不同，不能直接相减计算年龄。需要时钟偏差/误差界、boot_id 与端到端延迟预算，同步失效不执行自动视觉运动。检测丢失不自动回预设姿态，按已验证停止策略处理。详见 [视觉扩展设计](K230D_SYSTEM_DESIGN.md)。

## 9. 停止、复位与故障

上电/复位默认禁止输出。正常停止清队列并减速到零，维持最后 PWM 指令；失联同时取消旧控制权。保持 PWM 不表示实物一定不下垂。恢复建立新会话，不自动续跑。

急停要求独立输出/供电措施并锁存。PCA9685 OE 为低有效，拉高禁止正常 PWM 输出，实际输出电平按寄存器/硬件设定；OE 不切断舵机供电，也不是机械制动器。[NXP 数据手册](https://www.nxp.com/docs/en/data-sheet/PCA9685.pdf)

当前没有角度、电流或温度传感器证据，不承诺检测真实堵转、过热、滑齿或掉落。通信、版本、限位、I2C 与程序超时可软件检测，实际保护由硬件能力决定。第一次装配启用不自动全部回中，断电后实际姿态未知，应人工建立参考/逐轴标定。

## 10. 验收与打印条件

| 阶段 | 交付 | 必须验证 |
|---|---|---|
| S0 参数与模型 | GLB、碰撞体、参数、夹爪求解 | 零位、单轴/组合姿态与 Blender 一致，TCP 和哈希正确 |
| S1 上位机仿真 | 五轴操作、可达性、SEQ 与 SDK | 可行/不可行/未收敛区分；全路径、朝向、跳解、夹爪干涉 |
| S2 模拟固件 | 共用核心、模拟协议、日志回放 | 插补/停止、坏帧/重复/溢出/重连、各入口不能绕过限制 |
| S3 打印准备 | 候选模型、STL、装配清单 | S0–S2 通过，支承负载筛查、线缆/相机空间、试装计划 |
| S4 制作标定 | 接口试装、装配、标定表 | 脉宽/方向、逐轴范围、固定/供电、停止、无载低速联调 |
| S5 实物与视觉 | 误差报告、视觉任务 | 精度/延迟/温升/负载、视觉错误与控制源切换 |

软件以可重复样本和反例验收，不只看动画。必须包括：终点可达但途中碰撞；位置可达但朝向无解；接近边界后释放点动；执行中变更模型；视觉跨重启数据变旧等案例。

暂不指定未经计算的工作空间或保证精度。算法数值误差与实物毫米级误差分开记录。S3 通过表示具备制作样机的依据，不代表实物认证；接口试装仍先于整机打印。
