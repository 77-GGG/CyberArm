# CyberArm K230D 视觉扩展设计

版本：2.0｜2026-09-14｜状态：预留设计，尚未实现。与 [系统设计](CyberArm_设计文档.md) 一致：五关节加夹爪、MG996R×3 + MG90S×3，先仿真后制作。

## 1. 分阶段接入

K230D BOX + GC2093 负责图像、检测与跟踪，ESP 是运动控制权和输出的最终裁决者。首期不需要视觉板，用模拟观测验证接口。

| 模式 | 数据流 | 条件 |
|---|---|---|
| SIM | 模拟观测 → PC 策略/规划 → 模拟控制器 | 无硬件输出 |
| PC_VISION | K230D → UART → ESP 转发 → PC 策略/规划 → ESP | PC 在线、租约有效 |
| LOCAL_VISION | K230D → ESP 策略/求解/约束 → 轨迹执行 | 后续 MCU 算法与约束验证后启用 |

三种模式互斥，PC 断开不自动切入独立视觉。未实现能力返回 UNSUPPORTED。K230D 不发送舵机角度或直接写 PWM。

## 2. 板卡与结构

保留 ATK-DNK230D、GC2093、板卡专用 CanMV 方向。固件、nncase runtime、模型和后处理配套固定版本。官方例程提供 UART1/GPIO40～41，首期板间链路采用 115200、8N1。[板卡介绍](https://wiki.alientek.com/docs/Boards/Kendryte/DNK230D/start-guide/k230d-box-introduction/)、[UART 例程](https://wiki.alientek.com/docs/Boards/Kendryte/DNK230D/example-base/uart/)

接线前核对所持板卡版本、针序、电平和 ESP 引脚。TX/RX 交叉并共地，PH2.0 的 5 V 不作 GPIO 信号，不未经设计连接独立电源。具体 USB 口、摄像头接口按所持板原理图确认，不把旧文档描述当实测。

首期外置固定相机，模型预留可调支架、视锥、坐标系和线缆包络；视觉板置于基座旁，留散热与连接器空间。腕上相机须再核验质量、线缆、支承和手眼标定。

视频另走图像链路，115200 UART 只传结构化观测、状态、配置和时间同步。

## 3. 观测与运动意图

| 观测 | 对应意图 | 限制 |
|---|---|---|
| 人脸中心 | 朝向/图像误差跟踪 | 不假设有三维距离 |
| 指尖关键点 | 平面目标或有限方向跟随 | 未知高度不作三维抓取 |
| 颜色/类别物体 | 标定平面选物 | 明确高度、朝向和负载包络 |
| 手势 | 允许的离散动作 | 多帧确认、冷却、事件去重 |
| 深度/外部标记位姿 | 指定坐标系的三维目标 | 新传感器与标定验证后 |

观测包含 source_id、boot_id、frame_seq、采集/推理结束时间、model_id、calibration_id、坐标系、图像尺寸、类别、置信度、目标 ID、中心/框和深度有效标志。未知值不填 0 冒充测量。

策略将观测转成 MotionIntent，附来源序号和有效期，复用全路径/制动/边界检查。越界不裁成另一个抓取位置。夹爪指令完成不代表抓取成功，需视觉复核或额外传感器。

## 4. UART 草案

| 字段 | 字节 | 定义 |
|---|---|---|
| SOF | 2 | 0xCA 0x23 |
| version | 1 | 1 |
| type | 1 | 消息枚举实现时固化 |
| sequence | 2 | 小端，按模 65536 比较 |
| payload_len | 2 | 小端，最大 256 |
| payload | 0–256 | 明确类型化编码，不传 C 结构体内存 |
| CRC | 2 | CRC-16/CCITT-FALSE，结果小端 |

CRC 参数：poly=0x1021、init=0xFFFF、refin/refout=false、xorout=0，覆盖 version 到 payload。消息保留 HELLO、HEARTBEAT、SET_MODE、MODE_ACK、TARGET、GESTURE、STATUS、TIME_SYNC。各类型字节偏移/缩放/非法值和黄金字节样本在实现前固定，当前未声明可互通。

解析器限制长度、缓冲和组帧时间，坏帧扫描下一 SOF。序号回绕和重启分开处理。TARGET 只保留最新有效帧；离散事件走有界去重队列。MODE_ACK 报实际模式，加载失败不能虚报成功。

最大 266 B 帧、30 Hz 约 7980 B/s；115200、8N1 理论约 11520 B/s，还要留心跳/同步/配置预算。常用 TARGET 保持更小，大量关键点降频；不能一直用旧文档的 64 B 假设计算吞吐。

## 5. 时钟和有效性

boot_id 区分上电会话，capture 时间来自该会话单调时钟，不直接相减不同设备 uptime。TIME_SYNC 用往返测量估计偏差与误差界，PC_VISION 还计入 ESP 转发与 PC 规划延迟。同步失效、误差过大或 boot_id 改变时暂停自动运动并重新握手。

接收时间只能证明链路活跃，不能证明画面新鲜。按年龄上界检查，计入推理、排队与传输。初始目标年龄预算 150 ms、心跳 100 ms、300 ms 无有效来源触发停止，仅为联调起点，低帧率任务需重新评估，不静默放宽。

只有心跳没有新目标不维持运动。重复、乱序、跨会话、过期、低置信度与突跳不刷新动作有效期。观测序号关联 PC 返回轨迹，ESP 拒绝引用旧观测的动作。

## 6. 标定与模型

固定相机平面任务：畸变校正 → 单应性/外参 → 基座坐标 → 五轴求解 → 路径检查。保存内参、分辨率/裁剪、镜头设置、安装姿态、桌面平面、基座关系和版本；相机移动/裁剪变化使标定失效。

按模式加载模型，不默认所有模型并行。可参考 [正点原子 AI 框架](https://wiki.alientek.com/docs/Boards/Kendryte/DNK230D/example-ai/development_framework/)，实际内存、帧率和兼容组合在接入时测试。

腕上相机需要采集时刻的机械臂姿态；当前只有指令姿态，外参只能近似，不能宣称高精度手眼结果。完整三维定位需要明确深度来源。

## 7. 验收

模拟观测先覆盖正常、越界、朝向无解、突变、重复手势、丢失、时钟偏差、序号回绕、重启和返回动作过期，记录拒绝原因与停止过程。

接板后验证字节互通、电平、吞吐、时钟同步；再让真实观测驱动虚拟模型；最后低速、小范围驱动已标定实物。分别记录识别准确率、采集至动作延迟、指令轨迹和实物误差，不只用 FPS 判断效果。
