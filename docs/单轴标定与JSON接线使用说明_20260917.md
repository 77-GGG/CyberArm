# 单轴标定与 JSON 接线使用说明

适用固件：0.3.0。上位机源码已集成单轴标定工作台。没有自动烧录或实体舵机验收。

## 接线的唯一配置入口

编辑 [config/wiring.json](../config/wiring.json)：

| JSON 字段 | 默认值 | 意义 |
|---|---|---|
| i2c.sda_gpio | 8 | PCA9685 SDA 接 ESP32-S3 GPIO8 |
| i2c.scl_gpio | 9 | PCA9685 SCL 接 GPIO9 |
| i2c.clock_hz | 400000 | I2C 总线频率 |
| pca9685.address | 64 | 十进制 64 即 0x40；JSON 不接受 0x40 数字字面量 |
| pca9685.pwm_hz | 50 | PWM 公共频率 |
| pca9685.oscillator_hz | 25000000 | 名义振荡器频率；不是测量值 |
| axes | J1/J2/J3/J4/J5/G → 0/1/2/3/4/5 | PCA9685 通道从 0 开始 |

轴顺序固定 J1、J2、J3、J4、J5、G，可修改 channel 为 0–15 的六个不同通道。修改 SDA/SCL 前核对实际板卡，不使用 USB、存储器等被占用引脚。生成器校验支持的 GPIO 集合，但不能替代具体板卡接线检查。

PlatformIO 的 pre 脚本 [generate_wiring.py](../tools/generate_wiring.py) 每次构建读取 JSON，校验后生成 `.pio/build/generated-esp32-s3-devkitc-1/WiringConfig.h`。无需手动维护头文件；缺文件、非法值或重复通道会终止编译，不会静默使用旧配置。正常 upload 目标先构建，所以也会使用当前 JSON。直接用其他烧录器写旧 bin 不会读取新 JSON。

```powershell
# 在项目根目录执行
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run
# 将 COM5 替换为实际烧录端口
& "$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe" run --target upload --upload-port COM5
```

烧录后在上位机“调试 → 实机调试 → 通信”查看固件接线和摘要。它显示的是设备回报的编译配置，而非电脑猜测。接线 JSON 修改导致摘要变化后，旧标定不再自动生效，需要重新复核保存。

电源接线仍需人工完成：PCA9685 VCC 接适合 ESP32 的逻辑电源，V+ 使用舵机电源，地线共地。JSON 只描述软件可配置的总线与输出映射，不能改变实际接线。

## 从零调试一个舵机

1. 连接 ESP32-S3，确认固件版本 0.3.0 和 PCA9685 就绪。进入“回中与限位”。
2. 选择关节，初始窗口默认为 1400–1600 μs、初始脉宽 1500 μs、变化速度 50 μs/s。这些是测试起点，不是已标定值。
3. 断开传动或支撑机构后勾选确认，点击“开启选中舵机”。其他通道关闭。首次输出仍可能转动，因为没有实测位置反馈。
4. 用 ±1/±5 计数小步试转。一个计数的名义微秒数在界面显示；目标受窗口限制，固件拒绝超过 100 μs 的单次目标变化，连续输出受变化速度限制。
5. 对齐机械设计零位，点击“记录当前位置为关节 0°”。不要强扭已经啮合的舵盘修零。
6. 在“角度采样”用外部量具测量负向点与正向点，填写相邻连杆的相对角度，记录人工读数。零点加两侧点构成最小三点映射，最多七点。方向由单调脉宽映射决定，无需再额外反转。
7. 在“范围与保存”输入已经验证的负/正工作限位。必须包含零位，并在采样覆盖范围内。点击“关闭输出”，勾选实测确认，再点击“确认保存到 ESP32 并读回”。
8. 在“角度验证”重新开启单路测试，以已保存映射试转并记录量具读数。若目标距离当前脉宽超过 100 μs，分小步接近；不要靠加大单次跳变跨越未知区间。
9. 完成一轴后关闭输出再切换下一轴。切轴会保存电脑草稿。六轴分别确认后才允许整机使能。

“保持当前位置”保留输出、冻结目标继续变化；“关闭输出”停止 PWM，不等于锁住机构。顶部停止在单轴测试时关闭测试输出。

## 保存、版本和角度含义

- 点动和记录不会写 NVS。只有正式保存写入完整标定记录，并核对回包。
- 设备标定绑定模型、通道存储槽和接线摘要。原 0.1/0.2 固件的 min/center/max 参数不会被冒充为实测角度表；升级后需要重新确认。
- 上位机草稿和备份位于用户数据目录的 calibration 子目录。Electron 使用自己的 userData；开发/服务模式可用 CYBERARM_USER_DATA_DIR 指定路径。
- 可导出完整记录 JSON，导入只载入当前轴草稿，不自动使能或覆盖固件。电脑备份与设备版本不一致时展示提示，控制以设备回读为准。
- 关节角映射使用单调分段线性插值。缩小工作限位不会缩放角度比例。
- 整机规划与固件检查使用模型范围、实机工作范围和映射覆盖范围的交集。原 robot.json 不被修改。
- 界面中的名义脉宽按 PCA9685 计数和配置时钟换算；人工读数有记录时间；实时实测角保持为空。夹爪目前仍控制驱动角，不将其伪装为毫米开口或夹持力。

## 调试会话与运动互斥

工作台页面每 300 ms 续约，固件 1200 ms 未收到有效单轴会话续约则结束该通道输出。普通后台 heartbeat 不续这个租约。关闭页面主动结束，异常关闭由超时兜底。调试期间不能启动整机运动；切换通道必须先结束当前输出。

使能增加 ARMING 状态，以速度/加速度约束计算过渡时长，最少 600 ms。ARMING 阶段拒绝 target/prepare。仍然以最后指令角作为开始参考，不代表已知实体位置；实体被移动后不能保证第一帧无突动。

## 控制台与测试

新增结构化命令：`hwtest`、`hwmapping`、`hwdraft`、`hwrecords`。例如：

```text
hwtest {"action":"begin","axis":1,"pulse_us":1500,"low_us":1400,"high_us":1600,"rate_us_s":50,"confirmation":"SUPPORTED"}
hwtest {"action":"renew"}
hwtest {"action":"target","pulse_us":1520}
hwtest {"action":"hold"}
hwtest {"action":"end"}
```

控制台不会自动替你续调试租约，建议使用工作台；SDK 使用同一客户端 ID 调用上述命令并持续续约。旧 `hwcal/hwcenter` 在新固件上明确拒绝，提示改用工作台。

已验证：PlatformIO 编译、前端 TypeScript/Vite 构建、Python 40 项测试（其中包含实际 C++ 编译执行）、Electron 单轴工作台和原手动界面流程。硬件测试使用替身 I/O，不能证明实体接线、PWM 波形、负载运动或角度精度；本次未烧录设备。
