# 上位机单舵机调试与角度标定方案

日期：2026-09-17  
状态：设计基线；核心流程已于 2026-09-17 实现，当前操作及验证边界见 [单轴标定与 JSON 接线使用说明](单轴标定与JSON接线使用说明_20260917.md)。  
范围：ESP32-S3 + PCA9685 + 六路位置型 PWM 舵机。以下设计文字保留为需求基线。

本方案以本轮重新评估为准，替代此前对话中“自动扫到机械极限”“直接改写 robot.json”“保存临时脉宽就算标定完成”等建议。现有代码中的使能斜坡另有边界，见第 7 节。

## 1. 目标与可行性

可行。烧录一次支持本方案的固件后，通过上位机完成单轴使能/失能、脉宽点动、零位建立、人工测量辅助的角度标定、工作范围设置、验证与保存。日常修改标定值不需要重新编译或烧录。

上位机负责引导、计算、记录与展示；固件负责实际输出、模式互斥、范围检查、变化速率限制和持久化。普通三线舵机不提供可直接使用的外部位置回读，本方案不将输出命令或估计角度显示为实时实测值。

暂不涉及电气急停、供电切断链路或新增位置传感器。

## 2. 当前代码基础

- [ServoSubsystem.cpp](../lib/CyberArmFirmware/src/ServoSubsystem.cpp)：六路输出、单路中位、校准 NVS 存储。当前保存校准直接置 confirmed=true；角度按编译期限位与三个脉宽端点换算。
- [CommandProtocol.cpp](../lib/CyberArmFirmware/src/CommandProtocol.cpp)：USB JSONL 命令。当前中位测试要求该轴已经确认校准，改校准要求输出关闭。
- [MotionController.cpp](../lib/CyberArmFirmware/src/MotionController.cpp)：运动状态机和使能指令斜坡。
- [hardware.py](../simulator/backend/cyberarm/hardware.py)：上位机串口桥接。
- [server.py](../simulator/backend/cyberarm/server.py)：统一控制入口与后台心跳。
- [main.tsx](../simulator/frontend/src/main.tsx)：现有“实机调试”工作台。

目前可以先保存一组临时参数再测试中位，因此不是完全无法测试新舵机；问题是“参数已保存”和“实测标定已完成”被混为一谈，缺少独立、不写 NVS 的连续测试通道。

## 3. 用户操作流程

保持浅色工业工作台风格，在现有“调试 → 实机调试”中升级单轴调试区域，固定放置通道、输出状态、保持和关闭按钮，将较长说明集中在步骤说明区。

| 步骤 | 上位机操作 | 人工操作与确认 |
|---|---|---|
| 连接 | 枚举串口、握手、检查固件能力和驱动状态 | 确认通道接线 |
| 选择通道 | J1–J5/G 对应 PWM0–PWM5 | 选择待测舵机 |
| 单路使能 | 展示初始测试脉宽，明确确认后开启选中通道 | 首次测试断开传动，或可靠支撑机构 |
| 脉宽试转 | 单步增减、粗细步长、限制变化速度、保持 | 观察方向与位置变化 |
| 零位 | 记录当前测试位置为关节 0° | 按设计参考姿态安装舵盘并微调 |
| 角度标定 | 记录脉宽与人工角度读数，生成映射 | 测量输出关节的相对角度 |
| 工作范围 | 设置已经验证的可用角度及脉宽范围 | 小步验证无干涉的工作区间 |
| 验证 | 输入目标角、往返试验、填写读数 | 检查误差和重复性 |
| 保存 | 预览变更、确认写入、读回校验、导出记录 | 确认标定完成 |

“保持”停止指令继续变化并保留 PWM；“关闭输出”关闭 PWM，不能当作机械锁止。单路模式其余通道关闭，因此整机装配状态下要支撑其他关节。切换通道前结束当前通道输出，不自动开启下一路。

未完成角度标定时，主操作单位为脉宽/计数，不显示未经验证的绝对角度。标定后开放角度试转，并明确标注“标定换算角”。

## 4. 固件设计要求

1. 独立调试状态，与整臂使能、使能过渡和自动轨迹互斥。新舵机不需要伪造 confirmed 标记即可进行受限的单路脉宽测试。
2. 临时测试参数只存在内存中；显式确认保存才写永久存储。草稿与已确认标定分开，未完成草稿不能使整机校准状态变成 6/6。
3. 已连续输出的同一通道，从当前输出指令逐步变化到新目标。限制测试窗口、目标变化、速率；第一帧初始脉宽必须明确展示。
4. 上报测试通道、目标脉宽、输出计数、按时钟参数换算的名义脉宽、过渡状态、标定版本和保存结果。没有示波器测量时，不把名义脉宽称为“实测脉宽”。
5. 调试会话使用独立有效期/会话标识。只有拥有调试页面的客户端续约才延长输出；后台通用心跳不能无限续期。页面关闭、客户端失联或会话过期均结束单路输出。
6. 保存包含格式版本、模型/轴身份、映射点、工作范围和确认信息。验证数值有限、点序有效、映射单调、范围合法；使用完整记录的原子提交或等效机制，避免掉电留下半份有效校准。
7. 连接时上报能力与标定版本。旧固件仍可被识别，但不开放不支持的新向导。涉及旧命令语义变化时必须做明确兼容策略，不能只因 JSON 格式未变就认定完全兼容。
8. 普通运动同时执行角度范围、映射覆盖范围和速度/加速度检查；禁止通过缩放映射“挤进”范围。越界整条拒绝。

命令名称可在实现时确定，至少覆盖进入调试、设置测试目标、保持、退出/关闭、读取草稿、提交与读回标定。单路测试协议应先能被控制台/自动化测试调用，再接向导界面。

## 5. 角度处理的推荐方案

### 5.1 以机械关节为角度基准

区分三个量：舵机自身输出轴位置、机械关节相对于父连杆的角度、末端位置。用户控制机械臂时采用模型中的关节角度。不能把舵机标称 0–180° 直接当作模型关节角，也不能默认中位恰好是物理 90°。

建议先给每个关节建立可重复的零位参考：两条对齐刻线、可拆指针与量角盘，或定位工装。工装只用于建立参考，运动前移除会限制运动的部件。参考图必须以实际模型与装配为准，本方案不假定所有关节零位都是水平或竖直。

对俯仰关节，量具测量的是相邻连杆的相对角；测某一连杆相对地面的倾角时，要扣除父连杆倾角。对底座偏航、腕部滚转，宜用绕轴的角度刻度和指针。单根连杆的倾角读数不能通用于所有轴。

### 5.2 从三点开始，再按误差增加点数

首轮在已验证的小范围内测“负向点、零点、正向点”，分别拟合零位两侧斜率，不必先寻找完整 180° 行程。三点足够准确就保持简单；若中间验证点误差明显，再增加到 5–7 个点，用单调分段线性插值。避免高阶多项式在采样点之间过冲。

每个点保存：输出计数、名义脉宽、人工实测关节角、进入该点的运动方向、测量次数与试验负载。方向可由角度随脉宽的变化确定；展示给用户确认。映射本身已经包含方向时，不再额外反转一次。

将实测点写成 (q_i, p_i)，按关节角 q 排序。目标 q 在相邻两点之间时，采用：

```text
p(q) = p_i + (q - q_i) / (q_(i+1) - q_i) * (p_(i+1) - p_i)
```

示例仅用于说明计算，不能直接下发到实物：测得 -10°→1420 µs、0°→1500 µs、+10°→1590 µs，则 +5°→1545 µs，-5°→1460 µs。正负两侧比例可以不同。最终输出仍需计数量化。

不在已测范围外外推；需要扩大范围时先追加实测点和检查。装配存在传动比或非线性时，应测实际输出关节。若机构在该区间非单调、有多种构型或奇异位置，不能只靠一张单调表，应限制到已验证构型并检查机构模型。

### 5.3 映射与限位独立保存

角度映射描述“多少脉宽对应多少关节角”；工作限位描述“允许运动到多少角度”。缩小工作范围只改变允许集合，不改变同一目标角对应的脉宽。

正式运动有效范围 = 模型验证范围 ∩ 实机验证工作范围 ∩ 标定映射覆盖范围。

原始 robot.json 不被向导直接覆盖，也不自动扩大模型范围。实机配置单独保存，上位机规划进程与固件共同使用生效范围；配置变化使旧规划失效并刷新规划进程中的配置。若暂时不能保证各端同步，应禁止新配置下的整机执行。

### 5.4 先测重复性，再考虑补偿

测量从两个方向接近同一目标的结果，分别记录方向相关误差与同方向重复误差。固定偏差可修零位，比例误差可修映射；随机波动、负载挠度和回差不能靠增加标定点全部消除。

首版不自动做反向过冲补偿，它可能越过工作边界并改变已检查路径。可在专门试验中比较同向接近是否改善重复性，再决定后续算法。不给出未经实测的“必达 ±1°”或统一厘米精度承诺。

### 5.5 夹爪单独处理

夹爪驱动角与夹爪开口宽度是两个量，连杆机构可能让二者非线性。先保留驱动角控制；如需毫米输入，用卡尺测若干开口宽度与驱动角的对应点，在有效单调区间换算，再走现有驱动角模型。开口指令、实测开口、夹持力与抓取成功必须区分。

## 6. 数据与上位机联动

- ESP32 保存正式生效配置，上位机在用户数据目录保存草稿、测量原始记录与设备配置备份；安装目录中的资源不作为用户配置存储位置。
- 以设备身份、模型身份和通道绑定标定；重连时比对版本/摘要。冲突时展示差异，不静默覆盖。
- 保存过程采用“验证候选配置→固件提交→读回核对→主机生效”。写入失败或读回不一致时明确保持旧配置/禁用相关动作。
- 保留原始测量点，换拟合方法无需重测。更换舵机、重装舵盘、换传动或输出时钟配置后，需要复核标定。
- 前端分列：目标角、输出指令的标定换算角、人工测量记录（含时间）、实时传感器角（目前为空）。
- 保留导出/导入能力，但导入的文件不得直接被视为已在当前设备验证。

## 7. 必须明确的边界与历史更正

### 使能斜坡

现有 0.2.0 固件从上次指令姿态接通输出，再用 600 ms 曲线向目标过渡。没有位置反馈时，上次指令不等于当前位置；第一帧仍可能导致实体迅速追赶。固定 600 ms 也不自动满足任意角差下的速度/加速度限制。

实施新调试模式时还应补齐使能过渡状态，防止新的 target/prepare 提前覆盖过渡；上报忙状态及完成情况，并按允许速度/加速度选择时长。不能将它宣传为任意未知位置上电均无突动。

### 舵盘安装

先命令并记录参考脉宽，再在不改变输出轴参考位置的条件下选齿安装与固定。需要换齿时拆下重装，不能强扭已经啮合的舵盘来“修零位”。断开输出后若轴被移动，应重新建立参考再复查。残余小偏差通过零位脉宽修正，不假定每种舵机、舵盘都采用相同齿数。

### PWM 分辨率

按名义 50 Hz 与 4096 个计数计算，每计数约 4.88 µs。这是脉宽量化步长，不是实物角度精度。小于一个计数的脉宽变化可能不改变输出，也可能跨过量化边界，因此“所有 2–5 µs 调整都无效”不准确。界面提供按计数步进，并展示名义换算值；实际脉宽受时钟频率及预分频影响。

停止脉冲后是否持续保持力取决于具体舵机，不能统一承诺所有舵机立即完全松开。位置指令也不能证明实体到位。

## 8. 实现顺序与验收

建议按以下阶段实施，每阶段都可独立验证：

1. 固件单路测试状态、临时输出、超时与保持/失能；控制台可调用。
2. 三点/多点映射、范围校验、正式配置提交与重启读回。
3. 上位机向导、独立调试续约、数据记录及配置同步。
4. 自动规划的有效范围约束、使能过渡互斥及回归验证。

必要的软件测试包括：未标定轴测试；通道切换不误开其他输出；测试不写 NVS；普通心跳不能续调试租约；使能过渡不可被绕过；保持与失能区别；递增/递减映射、越界拒绝；改限位不改比例；无效/中断保存；重启读回；主机与固件标定不一致；无反馈时不显示实测角。固件关键状态与插值需要执行真实 C++ 的测试，不能只用 Python 假串口替代。

实机从断开传动的单舵机测试开始，验证 PWM、点动和退出行为，再逐轴装配标定，最后验证已支撑整机的小范围运动。验收记录包含输入、输出指令、人工测量、误差、负载与版本。本文没有声称完成任何新功能或实机验收。
