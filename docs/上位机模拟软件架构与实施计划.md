# CyberArm 上位机模拟软件架构与实施计划

版本：1.1 实施稿｜日期：2026-09-14｜状态：用户已授权开始，实施分支 features/simulator。

本文将系统设计中的上位机部分收敛成一个可交付的软件阶段。用户已授权开始实施；开发环境、模型导出和基础运动学核心已开始落地，后续按阶段推进。普通实现选择与通过测试后的下一阶段无需重复确认。界面以 DummyStudio 官方演示为参考，具体布局及功能状态见《上位机界面与功能说明》。以下未标注完成的条目均为实施要求，不代表已有功能。

## 1. 本轮目标与范围

交付一套在 Windows 本机运行、使用现有 RevC 外形和五轴运动链的中文机械臂模拟软件。无需连接舵机或开发板，可以操作关节、拖动末端、查看条件可达范围、编辑场景、预览轨迹、录制动作并回放。

机械基线：MG996R×3 + MG90S×3，五个运动关节与一个夹爪。接受构型的姿态限制；先用现有模型建立正确仿真，若发现轴心、联动、碰撞体或结构干涉问题，再在独立机械版本中修改并记录。原 RevC 留作对照。

本阶段包含几何运动学、关节轨迹、碰撞检查、控制状态机和模拟时钟。不实现重力接触动力学、结构有限元、真实摩擦/回差预测，不能用软件动画推断实物承载。可选扰动用于展示假设影响，不属于物理精度承诺。

视觉、摄像头、K230D、实机串口、PWM、ESP32 固件和打印均不进入本轮任务。仅保留通用输入适配器与控制器接口，不创建视觉页面或专用视觉模块。RoboDK、语音、IMU、外接示教器的具体适配也不在本轮；手柄预留输入协议，首轮先把鼠标、键盘、脚本做好。

## 2. 建议采用的技术架构

采用本地网页应用：启动脚本启动服务并打开浏览器。依赖安装完成后，运行不需要外网；模型、字体、脚本均随本地项目提供，不依赖 CDN。首版不引入 Electron、Unity、ROS 或商业仿真软件。

| 层 | 技术选型 | 责任 |
|---|---|---|
| 交互界面 | TypeScript + React + Vite | 中文面板、场景树、控制、时间轴、状态 |
| 3D 显示 | Three.js、GLTFLoader、OrbitControls、TransformControls | GLB、坐标轴、目标拖动、轨迹、碰撞提示 |
| 本地应用服务 | Python 3.12 + FastAPI + Pydantic | API、会话、来源仲裁、文件、任务与状态推送 |
| 规划层 | NumPy + SciPy | 五轴数值 IK、目标约束、工作空间采样、路径时间参数化 |
| 几何/执行核心 | 独立 C++，CMake 构建 | FK、夹爪联动、轨迹求值、基础碰撞与状态推进 |
| Python/core 接口 | C ABI + ctypes 加载本地 DLL | 明确的数组、长度、句柄、错误码，避免两套核心实现 |
| 数据保存 | 版本化 JSON、GLB、JSONL 日志 | 场景、动作、参数、回放与证据 |
| 验证 | CTest、pytest、前端测试及浏览器交互检查 | 数值/协议/边界与操作流程 |

C++ 核心限制为可移植的小模块，不依赖 Arduino、I2C、USB、Python 或图形引擎。桌面调用边界固定为 C 类型，不跨 DLL 传 STL 对象或释放对方分配的内存，异常转明确错误码。将来移植 MCU 只复用适合的部分，不承诺桌面版本无需适配就能烧录。

官方文档已确认 Three.js 的模型加载/变换工具、FastAPI 的 WebSocket、SciPy 的带边界最小二乘和 ctypes 的 DLL 调用能力；这些工具本身不提供适配 RevC 的完整机械臂求解器，运动逻辑仍由本项目实现。[Three.js](https://threejs.org/docs/pages/GLTFLoader.html)、[变换控件](https://threejs.org/docs/pages/TransformControls.html)、[FastAPI](https://fastapi.tiangolo.com/advanced/websockets/)、[SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)、[ctypes](https://docs.python.org/3/library/ctypes.html)

### 数据流

```text
鼠标 / 键盘 / 数值面板 / 时间轴 / Python SDK
                     ↓ MotionIntent
本地服务：当前来源、会话、参数版本、任务状态
                     ↓
规划：IK / MoveJ / MoveL / 路径与制动检查
                     ↓ 不可变 TrajectoryPlan
模拟控制器：唯一执行状态、固定步长、停止/暂停
                     ↓ RobotState + 连杆变换 + 事件
3D 视图 / 状态面板 / 轨迹记录
```

“预览”生成计划和目标分身，不改变正在执行的机械臂；“执行”消费已验证计划。界面不自行决定安全，不把拖动目标直接赋给当前姿态。模拟控制器是运行状态的唯一所有者。

### 并发与运行方式

服务用单个执行所有者推进模拟控制器。IK、空间采样和长路径检查放入独立规划工作进程，避免阻塞 WebSocket 与 STOP。每个规划结果携带输入版本和状态序号，过期结果不回写当前目标。连续拖动合并请求，只保留最新待求解目标；旧任务可取消。

离线测试使用可手动推进的固定步长时钟；交互模式由本机单调时钟驱动同一个核心，初始执行步长 20 ms。界面渲染目标 60 fps，机器人状态可按 50 Hz 推送；首版直接显示最新权威状态，不独立外推机械臂动作。应用卡顿/系统休眠时暂停并提示，不一次追赶大量过期运动。

本地服务只监听回环地址，前端使用同源连接和启动会话标识。浏览器断连/点动失焦终止当前交互来源，模拟器按停止策略处理。首版不开放局域网控制。

## 3. 模块边界与单一数据来源

| 模块 | 输入 | 输出/约束 |
|---|---|---|
| ModelImporter | RevC Blender 总装 | GLB、关节参数、碰撞代理、参考姿态 |
| RobotModel | 版本化参数和关节角 | 由核心计算的五轴/夹爪变换、TCP |
| KinematicsPlanner | 目标、姿态策略、起始关节 | 解、残差、失败分类、连续性信息 |
| CollisionChecker | 配置/轨迹、场景、工具包络 | 通过/拒绝、碰撞对象、最小间隙或保守界 |
| WorkspaceSampler | 模型、限制、场景和姿态条件 | 可视采样缓存，不作为执行许可 |
| TrajectoryPlanner | MoveJ/MoveL/点动意图 | 分段轨迹、时间、速度/加速度、停止包络 |
| SimController | 已验证计划、停止、时钟 | 状态、事件、执行进度、连杆矩阵 |
| ActionStore | 关键帧和任务 | 可导出/导入动作、版本绑定和重验证 |
| InputAdapter | 界面/键盘/SDK | 相同 MotionIntent，不访问底层执行对象 |

FK 和夹爪闭链求解放在 C++ 核心，Python IK 每次迭代调用核心 FK；界面消费连杆矩阵，不再写另一套 IK/FK。碰撞代理也由相同几何变换驱动。核心中的轨迹求值同时用于预览检查与运行，避免两种插补造成分歧。

GLB 仅存显示资产，机器人参数存轴心、方向和固定变换。导出器统一处理 Blender Z-up、glTF 坐标约定和基座参考系，防止重复旋转或缩放。所有转换有对照样本，不能根据外观看起来相似就判定正确。

## 4. 模型和数据文件

建议实施时创建以下目录；本轮仅约定结构：

```text
simulator/
  frontend/             React + TypeScript + Three.js
  backend/cyberarm/      API、规划、存储、模拟控制器封装
  core/                 可移植 C++ 核心、C ABI、CTest
  sdk/                  Python 调用入口和示例
  assets/revc/           robot.glb、robot.json、collision.json
  schemas/              意图、计划、状态、动作数据格式
  tests/                数值、路径、故障、交互样本
  scripts/              导出、安装、构建、启动、验收
  examples/             基础操作、动作回放、拒绝案例
  workspace/            用户场景和动作，不混入源资产
  reports/              版本与验收日志
```

robot.json 定义五关节顺序、父子链、本地轴、固定变换、保存姿态、仿真限位与依据、速度/加速度、TCP、夹爪有效区间。实物标定单独为空；初始历史预览角域可作为开发约束，但界面标注“临时仿真范围”，未经几何检查不扩大。

collision.json 定义每段连杆、底座、舵机突出部分、夹爪和五金的保守代理。第一版使用多个胶囊/球/盒等简单体组合，尽量包住实际几何；关键狭窄接口提高代理精度，避免单个大盒造成大面积误拒绝。邻接接触按局部允许关系登记，不能整体忽略相邻连杆而漏掉其他部位碰撞。

场景保存桌面、基座固定关系、可添加的盒状障碍/禁入区和工具/负载几何包络。动作保存关键帧与运动类型、时间参数、等待、夹爪、有限循环；不保存任意可执行代码。Python 脚本通过独立 SDK 运行。

参数、工具、场景和几何形成组合哈希。修改任一相关项使旧空间缓存/计划失效。动作可保留为待重新验证的意图，不能直接沿用旧轨迹。

## 6. 运动学、路径与边界

### 五轴求解

从实际模型链建立 FK，不硬套 Dummy 六轴 DH 参数。数值 IK 用关节边界、多起点和上一姿态初值；位置残差以米、朝向残差以弧度计算，显式设置尺度，求解后独立检查硬约束。软偏好不允许掩盖位置/硬朝向超差。

位置优先：满足 XYZ，姿态选择偏向连续与远离限位。带朝向约束：首期选择具体工具方向约束，不同时要求完整任意三维旋转。目标位置与方向是否可同时满足取决于本机构和当前区域，以残差判断。无收敛显示“未找到解”，与已知越界/碰撞不同。

MoveJ 采用同步关节插补，末端通常不走直线。MoveL 对笛卡尔路径自适应离散、连续求解并生成分段关节轨迹，然后再次检查分段插补的实际 TCP 偏差、限位、速度及碰撞。不能只验证笛卡尔采样点，就认定关节插补保持直线。

### 碰撞与制动

所有入口检查整个机器人和完整运动段，包含夹爪及负载包络。采用保守距离/位移界自适应细分；对无法排除碰撞的区间继续细分，到精度/资源界限仍不能确认时拒绝，不能无条件当作安全。细分容差、碰撞余量和允许接触表写入配置与报告。

空间采样用于提示，可按当前姿态条件切换；显示条件和分辨率，不把凸包当成无孔洞可达体。执行仍对具体请求重新检查。

每条可执行轨迹必须保留可验证停止能力。MoveJ 首期采用固定几何路径加可调时间进度，STOP 沿已经验证的剩余路径减速，不另接未经检查的捷径；限速同时约束剩余可用路径长度。MoveL 同样沿已验证分段路径停止。连续点动采用有限前视、随时可停的有效路径段，前视不足则减速。停止过程的速度/加速度及扫掠也要验证。

若当前导入场景已经穿模，报告初始碰撞并禁止运行；可以在编辑状态修正目标/场景，但不能通过执行按钮绕过检查。自动寻找绕障路线不列入第一版，直达路径被阻挡时明确拒绝。

## 7. API 与执行一致性

HTTP 用于项目、参数、规划、执行和停止请求，WebSocket 推送进度、状态和事件；Python SDK 访问同一服务。未来控制器传输接口保留，但本轮仅有 SimTransport。

关键对象：MotionIntent、TrajectoryPlan、RobotState、ActionProgram。Pydantic/JSON Schema 固定字段、单位和版本，前端类型据此生成或校验，不能各自随意维护。

规划返回 plan_id、起始状态序号、组合版本、轨迹定义、残差、检查结果和有效期。执行时再次核对当前状态和版本，变化则拒绝旧计划并要求重新规划；执行同一份计划，不在执行时用不同算法重新生成路径。

控制器提供 READY、RUNNING、STOPPING、PAUSED、FAULT 等状态，区分目标、指令轨迹与模拟状态。普通暂停先完成受控停止，继续从停止状态重规划剩余动作；日志回看/时间轴拖动使用另一个只读回放实例，不倒拨活控制器时间。任何来源不能绕过停止和版本约束。

桌面模拟 API 和未来 USB 固件协议不是同一个层级：前者可传场景/计划，后者按能力转换为执行指令。既有固件文档中的串口字段仍是后续草案，本轮不冻结其全部字节格式。

## 8. 实施阶段与交付

| 阶段 | 工作 | 可审阅结果 | 完成标准 |
|---|---|---|---|
| P0 基础环境 | 建立目录、独立依赖锁、核心 DLL/服务/网页最小联通 | 能启动的空白项目与环境说明 | Windows 构建、ctypes 往返、无网络运行路径可用 |
| P1 模型基线 | 读取 RevC、导出 GLB/参数、轴/TCP/夹爪、碰撞代理 | 真实模型与参数核对图 | 基准姿态、单轴及组合姿态与 Blender 对照通过 |
| P2 交互骨架 | 3D 场景、关节/夹爪目标、状态、场景编辑 | 可查看/编辑的机械臂工作台 | 目标与执行态分开，轴方向正确，临时范围明确 |
| P3 运动学与边界 | 五轴 IK、条件范围、自碰撞/桌面/障碍检查 | 拖动目标及可达/拒绝说明 | 硬约束独立验证，求解失败分类，路径反例正确拒绝 |
| P4 模拟执行 | 固定时钟、MoveJ/MoveL、点动、制动、暂停与重连 | 按轨迹运行并可停止的模拟器 | 预览/运行一致，速度/加速度/停止边界通过 |
| P5 动作与 SDK | 关键帧、时间轴、持久化、回放、Python 示例 | 可保存和复现的动作项目 | 导入重验，版本失效、多个来源仲裁通过 |
| P6 集成验收 | 边界回归、故障注入、性能和启动交付 | 软件、示例、测试报告、使用说明 | 核心功能无已知阻塞缺陷，所有列出的反例通过 |

P0 → P1 → P2 → P3 → P4 → P5 → P6。P2 的模型编辑不是宣布运动安全；完整可执行能力在 P3/P4 后交付。实现期间可以迭代界面，但不能用美化替代边界与轨迹验证。

每阶段保存结果并报告已完成/失败/待解决事项；测试不通过先解决或明确缩小能力，不将失败功能悄悄算作完成。需要改变五轴结构或实质削减本计划交付范围时再向用户说明；普通模块实现无需逐项询问。

## 9. 验收清单

以下数值是拟定的软件验收阈值，不是实物精度或本机已测性能。

| 类别 | 验收要求 |
|---|---|
| 模型一致性 | 基准+每轴正负样本+至少 30 组组合姿态；核心与 Blender 对照，TCP 差 ≤0.1 mm、姿态差 ≤0.1° |
| 夹爪一致性 | 有效开度区间至少 21 点，闭链分支连续，关键点位置与 Blender 差 ≤0.1 mm |
| IK | 固定随机种子，从已知合法姿态生成至少 100 个可达目标；有效解硬位置残差 ≤0.5 mm、启用的方向约束 ≤0.5°；未解出如实失败，不伪造成功 |
| IK 可用性 | 已知可达集首轮成功率目标 ≥95%；失败样本记录原因并改进，不能只报告成功样本的误差 |
| MoveL | 以实际分段关节插补回算 TCP，整段最大直线偏差 ≤0.5 mm；超差细分或拒绝 |
| 轨迹 | 起止与同步时间正确；速度/加速度全段不超配置；预览与执行用同一求值器及计划 |
| 边界 | 终点合法但途中撞桌/自碰撞/碰障碍、姿态不满足、夹爪越界、制动距离不足全部拒绝或提前停止 |
| 控制 | 松键/失焦/断连、STOP、暂停继续、状态变化、模型变更、重复执行和过期计划均有正确结果 |
| 回放 | 固定时钟/同版本/同输入重放结果一致；回看不改变活控制器；导入动作重新验证 |
| 性能 | 在本机默认 RevC 场景和约定障碍数量下记录指标；视图目标 ≥30 fps、普通单目标预览 P95 ≤200 ms；长规划可取消且不阻塞停止 |
| 交付 | 首次依赖准备后可离线启动；保存/重开项目有效；有版本锁、使用说明及原始验收日志 |

STOP 到软件进入 STOPPING 的本机交互目标 ≤100 ms，完成停止时间由当前速度和约束决定，不能把 100 ms 当作机械制动时间。碰撞/IK 的数值容差不等于实物间隙，应另行实测。

P6 必须保存至少三组演示：关节与末端操作；关键帧动作回放；边界/碰撞拒绝与停止。算法测试、浏览器交互和性能记录分别提供，不能以动画顺畅证明路径正确。

## 10. 已核对的环境与实施风险

本轮只读检查发现 Windows 上可调用 Node 24.15.0、G++ 16.1.0、CMake 4.3.2，以及已有运行时 Python 3.12.14/NumPy。检查的该 Python 环境没有 SciPy、FastAPI、pytest；不代表整台机器均未安装。P0 在项目独立环境准备依赖并锁版本，不改动用户全局包环境。

Blender 未在当前 PATH/常见安装位置检查中定位，P1 需从已有建模工具配置找到实际可用实例/可执行文件；尚未证明无法使用。此项在执行前期处理，不要求现在安装或修改模型。

主要风险是 RevC 轴/TCP/闭链定义、保守碰撞代理过粗、五轴 IK 分支与奇异区、停止路径连续性和 Windows DLL 打包。对应 P0/P1/P3/P4 分别先验证；若碰撞代理造成误拒，细化代理，不关闭碰撞检查。

已有结构载荷问题仍保留在总台账，本阶段不把它们变成视觉/硬件开发任务，也不将 P6 通过视作可以直接跳过打印准备审查。
